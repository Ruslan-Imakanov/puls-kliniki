# Пульс клиники

Управленческий учёт для частной клиники: деньги, прибыль, долги, мощность, врачи, услуги, маркетинг и склад в одном месте.
Самостоятельный проект (раньше жил в репозитории табеля, перенесён с историей коммитов).

Требования, по которым сделан продукт: [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md).

**Сайт:** https://puls-kliniki.imakanovr.workers.dev — Cloudflare Workers (статические файлы), выкладывается вручную
загрузкой содержимого `public/` через панель Cloudflare. Обновить = загрузить папку заново («Новое развертывание»).
Лимит Cloudflare — 25 МБ на файл. На Netlify (команда Qadam) есть пустой проект `puls-kliniki` — не используется,
у команды закончились кредиты.

| Адрес | Что это |
|---|---|
| `/` (`public/index.html`) | Продающая страница: возможности, экраны, ролик, цены, вопросы, форма заявки |
| `/app.html` | Программа: вход по почте, выбор или создание клиники, команда с ролями |
| `/app.html?demo` | Демо-клиника в браузере, без входа (данные — в `localStorage`, в базу не уходят) |
| `/privacy.html`, `/terms.html` | Политика конфиденциальности и оферта (реквизиты ИП внесены, проверить с юристом) |
| `/admin.html` | Панель владельца сервиса: клиники, подписки, продление |

Обучающий ролик и его сборка — в [`video/`](video/README.md). Реклама: промо-ролик, картинки, тексты, таргет,
скрипты продаж — в [`marketing/`](marketing/ads.md).

## Разделы
| Раздел | Что показывает |
|---|---|
| Обзор | Главные цифры за период, график с прогнозом, сигналы «требует внимания» (кассовый разрыв, просроченные долги, низкая загрузка, неявки, низкая маржа, отклонения от плана, склад) |
| Операции | Журнал доходов, расходов, переводов: поиск, фильтры, добавление (клавиша N), копирование в Excel |

| Движение денег | ДДС по дате оплаты (операционная, инвестиционная, финансовая деятельность), остатки по счетам, прогноз остатка на 3 месяца |
| План-факт | Бюджет по статьям с вводом в таблице, отклонения, точка безубыточности, запас прочности |
| Долги | Дебиторка (ДМС, фонд, рассрочки) и кредиторка: старение долгов, оборачиваемость, отметка оплаты (в т.ч. частичной), отказы страховой |
| Мощность | Загрузка врачей, кабинетов, оборудования; потенциал выручки до целевой загрузки; узкие места; тепловая карта; сценарий «что если»; ввод часов |
| Врачи и зарплата | Выручка, выручка за час, средний чек, повторные, неявки, кросс-выручка; расчёт зарплаты по схеме (оклад, процент, оклад + процент, процент от маржи) и начисление |
| Услуги | Себестоимость (материалы по нормам, врач, эквайринг, накладные), маржа, маржа за час, ABC-анализ, ввод объёмов продаж |
| Маркетинг | Воронка по каналам: обращения → записи → визиты → новые пациенты; CPL, CAC, ROMI, LTV, LTV/CAC |
| Склад | Остатки, партии и сроки годности (FEFO), приход, расход, списание по нормам услуг |
| Загрузка из Excel | Импорт XLSX/CSV (в т.ч. Windows-1251 из 1С): автоподбор колонок, проверка, защита от дублей, создание недостающих справочников |
| Справочники | Статьи (группа определяет место в ОПиУ/ДДС), отделения, врачи, ресурсы, счета, контрагенты, каналы, номенклатура |
| Настройки | Параметры расчётов, команда и роли (приглашение по почте), смена клиники, резервная копия, журнал изменений; демо и очистка — только у владельца |
| Выгрузка в Excel | Кнопка «Скачать Excel» в каждом отчёте и «Скачать всё в Excel» в настройках: настоящие таблицы с формулами (итоги, маржа, загрузка, потенциал пересчитываются при изменении синих ячеек), листы с пояснениями «как считается» |

## Как устроено
- Чистые HTML/CSS/JS без сборки, ES-модули (`public/js`). Запуск локально: `cd public && python3 -m http.server 8080`.
- Все расчёты — чистые функции в `js/calc.js`. Ключевое правило: у операции две даты — `date` (оказание услуги / начисление → ОПиУ)
  и `paid` (движение денег → ДДС, пусто = долг).
- Состояние программы — один объект в `js/store.js`. В демо-режиме он хранится в `localStorage`.
  В рабочем режиме `js/cloud.js` подменяет сохранение (`hooks.persist`): после каждого изменения сравнивает строки
  с последним снимком базы и отправляет в Supabase только изменённые и удалённые строки (очередь с повтором при
  обрыве связи, предупреждение при закрытии вкладки, если что-то не отправлено). Если база отказала по правам —
  изменение откатывается с подсказкой. Данные перечитываются при возврате на вкладку.
- **База — Supabase-проект `puls-kliniki`** (`zqptdixqcatezflrmzxu`, Франкфурт, бесплатный тариф).
  Схема и правила доступа — [`schema.sql`](schema.sql). Каждая строка любой таблицы принадлежит клинике
  (`clinic_id`); RLS пускает только участников клиники. Роли: `owner` — всё, включая команду; `accountant` — финансы и
  клинические данные; `manager` — клинические данные (часы, приёмы, услуги, склад, маркетинг), финансы только читает;
  `viewer` — только чтение. Вспомогательные функции прав лежат в схеме `private` (не видна через API).
  Регистрация клиники — `create_clinic()`, приглашения по почте — `accept_invites()` (срабатывает только для
  подтверждённой почты). Заявки с сайта — таблица `leads`: аноним может только добавить строку, читать — только владелец
  проекта в панели Supabase.
- В коде фронтенда только публичный (publishable) ключ — защита данных в RLS. Секретный ключ не использовать нигде в `public/`.
- Выгрузка в Excel — `js/export.js` (библиотека xlsx-js-style лежит в `js/vendor/`, Apache-2.0; supabase-js — там же, MIT).
- Один файл для показа/публикации: `python3 tools/build_artifact.py out.html [--standalone]` — собирает только демо-режим.

### Подписки и админ-панель
- У каждой клиники `plan` (пробный / Старт / Клиника / Сеть) и `paid_until`. Новая клиника получает 30 дней пробного периода.
  Состояние считает база по своей дате: `trial`/`active` → после даты `grace` (10 дней, всё работает, программа напоминает)
  → `expired` (только просмотр: правила доступа не пускают запись, выгрузка в Excel работает). Баннер «заканчивается через N дней»
  появляется за 5 дней.
- Владелец клиники сам продлить подписку не может (триггер `guard_billing`). Продлевает владелец сервиса в **`/admin.html`**:
  список клиник, кому скоро платить, «Продлить» (сумма подставляется по тарифу, платёж пишется в журнал), «История», «Изменить», «Написать».
  Доступ — только аккаунтам из таблицы `platform_admins` (добавить: `insert into public.platform_admins select id from auth.users where email = '…'`).
- Миграции — [`migrations/002_billing.sql`](migrations/002_billing.sql) и [`migrations/003_fixes.sql`](migrations/003_fixes.sql)
  (обе уже применены к проекту `puls-kliniki`). Для нового проекта: `schema.sql` → `002` → `003`. Дата подписки считается по
  времени Казахстана (Asia/Almaty). Проверка — `tools/test_billing.sql` (28 проверок).
- В админ-панели внизу — **заявки с сайта** (имя, телефон со ссылкой на WhatsApp, клиника, тариф и метка рекламы).
- Оплата пока вручную: клиника платит по счёту, вы продлеваете в админ-панели. Автоплатежи (эквайринг) — следующий шаг:
  платёжный сервис вызывает функцию-вебхук, она продлевает `paid_until`.

### Проверки
- `node tools/test_export.mjs` — формулы в выгруженных Excel-файлах дают те же числа, что программа (нужен LibreOffice).
- `tools/test_rls.sql` — изоляция клиник и права ролей (27 проверок внутри транзакции с откатом): вставить в SQL Editor
  Supabase и выполнить: в результате все строки должны быть с `ok = true`.

### Что настроить в Supabase перед реальными клиентами
1. **Authentication → URL Configuration:** Site URL `https://<сайт>/app.html`, Redirect URLs `https://<сайт>/**` —
   иначе ссылки из писем подтверждения и сброса пароля ведут не туда.
2. **Authentication → SMTP:** своя почта для писем (Resend, Brevo, Mailgun и т. п.). Встроенная почта Supabase
   отправляет письма только участникам команды проекта и с жёстким лимитом в час.
3. Резервные копии: бесплатный тариф их не делает — раз в неделю `pg_dump` или переход на платный тариф.
4. Закон РК о персональных данных требует хранить базы с ПДн граждан РК в Казахстане — см. предупреждение
   в `public/privacy.html` и решите вопрос до запуска.
